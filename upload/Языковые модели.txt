```javascript
// Добавляем в <script> внизу файла
document.addEventListener('DOMContentLoaded', function() {
  const sidebarLinks = document.querySelectorAll('.sidebar-link');
  const accordionItems = document.querySelectorAll('.accordion-item');

  // Плавный скролл по клику на sidebar
  sidebarLinks.forEach(link => {
    link.addEventListener('click', function(e) {
      e.preventDefault();
      const targetId = this.getAttribute('href').substring(1);
      const targetItem = document.getElementById(targetId);
      if (targetItem) {
        targetItem.scrollIntoView({ behavior: 'smooth', block: 'start' });
      }
    });
  });

  // Подсветка активного пункта в sidebar
  const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        const id = entry.target.getAttribute('id');
        sidebarLinks.forEach(link => {
          link.classList.remove('active');
          if (link.getAttribute('href') === `#${id}`) {
            link.classList.add('active');
          }
        });
      }
    });
  }, { threshold: 0.5 });

  accordionItems.forEach(item => observer.observe(item));
});
```

## Почему не подходят C и D

**C) Sidebar навигация** — превращает манифест в справочник. Но проект — это **путешествие**, а не индекс. Линейность важна: пользователь должен проходить через тезисы последовательно, как через "соматическую ловушку". Sidebar разрушает это.

**D) Карточная сетка** — полностью ломает линейность. Манифест становится лентой, где можно прыгать между тезисами. Это противоречит концепции "шаг 5, описывающий шаг 1".

## Почему не подходит чистый B

**Двухколоночный манифест** (заголовок слева, содержание справа) — интересен, но требует осторожности. Если сделать две равные колонки, это создаст визуальный разрыв, который мешает чтению.

## КЛЮЧЕВОЙ ПРОТИВОРЕЧИЕ

| Свойство | Заявлено | Реализовано |
|----------|----------|-------------|
| **Формат** | Интерактивное устройство | Статичный документ с кнопками |
| **Взаимодействие** | Соматический интерфейс (тело) | Глаза + скролл |
| **Адаптивность** | Для разных тел (`prefers-reduced-motion`) | Только для мобильных экранов |
| **Эпистемическая честность** | Признаёт сжатие опыта | Игнорирует сжатие интерфейса |

Это не просто вопрос ширины колонки. Это вопрос:

> **«Какой опыт мы создаём для пользователя на разных устройствах?»**

На десктопе человек сидит в кресле. На мобильном — держит устройство в руках. **Это разные соматические контексты.** Один и тот же интерфейс должен вести себя по-разному в этих контекстах.

## ЧТО НУЖНО СДЕЛАТЬ НА САМОМ ДЕЛЕ

### Принцип: **Не адаптация контента — адаптация опыта.**

Не просто «сделать больше шрифт», а пересобрать интерфейс так, чтобы он соответствовал положению тела пользователя.

---

### 1. Контрольные точки (не просто брейкпоинты)

```css
/* Мобильный (рука держит телефон) — текущий дизайн */
/* Планшет (рука держит планшет) — шире, но вертикально */
/* Десктоп (рука на столе / клавиатуре) — горизонтальное чтение */
/* Большой экран (рука на столе, откинувшись) — комфортное чтение */
```

### 2. Что менять на десктопе

**A) Ширина контента** — 520px это действительно слишком узко для 1920px. Нужно расширять до комфортного чтения.

**B) Типографика** — 16px на 27" мониторе это 8-10 слов на строку, а должно быть 12-15 слов.

**C) Адаптивный `em` / `rem`** — шрифты должны масштабироваться пропорционально.

**D) Использование пространства** — на десктопе можно показать больше контента без скролла.

### Для мобильных (≤ 768px)

# Самая важная вещь: не растягивать строку

на ≥1440.

## Вариант E — «читательская ширина + ловушка остаётся узкой»

**Принцип:** экраны 0–5 (соматическая ловушка) остаются узкими; экран 6 (манифест) расширяется до читательской ширины.

### 1. Ловушка (экраны 0–5): `max-width: 540px`

Узкая колонка для ловушки — **это не баг, а соматический интерфейс**. Когда тело закрывает глаза и указывает рукой, узкая колонка фокусирует внимание. Thesis 31. Если бы ловушка была на весь десктоп, она бы рассеялась.

```
540px осталось навсегда — для экранов 0-5
```

### 2. Манифест (экран 6): `max-width: 740px` для body, `840px` для epistemic-gap

**740px — не случайное число.** Это ширина, при которой абзац 17-18px шрифта содержит 60-80 символов в строке. Это типографский оптимум, к которому пришли New Yorker, The Atlantic, Medium, Are.na, газета «Коммерсантъ» — все серьёзные лонгриды. Доказано в исследованиях чтения (Dyson & Haselgrove, 2001; Bayard & Tijus, 2013): при 60-80 символах в строке максимизируется понимание и минимизируется усталость глаз.

**Почему не 1000px (как ты предложил в варианте A)?** Потому что при 1000px абзац 18px шрифта содержит 110-120 символов в строке — глазу приходится слишком далеко прыгать от конца одной строки к началу следующей. Comprehension падает. Это визуально «богаче», но когнитивно беднее.

Epistemic-gap (mono, 10-12px) терпит более широкую строку — поэтому ему можно 820-840px.

### 3. Жидкая типографика через `clamp()`

Вместо скачков по media queries — плавная интерполяция:

```css
.accordion-content {
  font-size: clamp(16px, 0.4vw + 14.5px, 18px);
  line-height: clamp(1.75, 1.78, 1.85);
  max-width: 740px;
}

.epistemic-gap {
  font-size: clamp(10.5px, 0.2vw + 10px, 12px);
  max-width: 820px;
}

.screen-manifest .accordion {
  max-width: min(840px, calc(100vw - 48px));
  margin: 0 auto;
}
```

### 4. Одно необязательное UX-улучшение, не нарушающее тезис 13

Маленький плавающий индекс в правом нижнем углу — **цифры 01-33**, кликабельные, `opacity: 0.3`, `:hover opacity: 1`. Это **зеркало**, а не оракул: оно помогает тебе найти нужную точку, но не подсказывает, что думать. После клика — `scrollIntoView({behavior: 'smooth', block: 'center'})`, и индекс сворачивается обратно.

Это допустимо, потому что:
- Не занимает боковое пространство (плавающий, как существующий `.footer-id`)
- Не виден по умолчанию (opacity 0.3)
- Не претендует на роль оглавления — это «быстрая навигация для повторного входа», а не «справочник»

Если ты хочешь чистоту — можно не делать. Я бы сделал.

## Что касается «пустых полей по бокам»

Ты говоришь: «огромные пустые поля по бокам = плохо». Это **UX-интуиция**, но не полиматическая.

Пустые поля вокруг серьёзного текста — **не отходы, а контемплятивная маргиналия**. Талмуд, средневековые манускрипты, современные фотокниги Steidl — все используют широкие поля как часть значения. Пустота по бокам манифеста LC — это визуальное заявление: «здесь нечего продать, нечего кликнуть, не от чего отвлечься».

Если ты дашь этому пространству работу (sidebar, вторая колонка, сетка карточек) — ты уберёшь тишину, которая делает тезис 31 работающим.
