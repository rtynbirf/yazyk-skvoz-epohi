   234→   234→#### **JavaScript для синхронизации скролла**
   235→   235→```javascript
   236→   236→// Добавляем в <script> внизу файла
   237→   237→document.addEventListener('DOMContentLoaded', function() {
   238→   238→  const sidebarLinks = document.querySelectorAll('.sidebar-link');
   239→   239→  const accordionItems = document.querySelectorAll('.accordion-item');
   240→   240→
   241→   241→  // Плавный скролл по клику на sidebar
   242→   242→  sidebarLinks.forEach(link => {
   243→   243→    link.addEventListener('click', function(e) {
   244→   244→      e.preventDefault();
   245→   245→      const targetId = this.getAttribute('href').substring(1);
   246→   246→      const targetItem = document.getElementById(targetId);
   247→   247→      if (targetItem) {
   248→   248→        targetItem.scrollIntoView({ behavior: 'smooth', block: 'start' });
   249→   249→      }
   250→   250→    });
   251→   251→  });
   252→   252→
   253→   253→  // Подсветка активного пункта в sidebar
   254→   254→  const observer = new IntersectionObserver((entries) => {
   255→   255→    entries.forEach(entry => {
   256→   256→      if (entry.isIntersecting) {
   257→   257→        const id = entry.target.getAttribute('id');
   258→   258→        sidebarLinks.forEach(link => {
   259→   259→          link.classList.remove('active');
   260→   260→          if (link.getAttribute('href') === `#${id}`) {
   261→   261→            link.classList.add('active');
   262→   262→          }
   263→   263→        });
   264→   264→      }
   265→   265→    });
   266→   266→  }, { threshold: 0.5 });
   267→   267→
   268→   268→  accordionItems.forEach(item => observer.observe(item));
   269→   269→});
   270→   270→```

   314→   314→## Почему не подходят C и D
   315→   315→
   316→   316→**C) Sidebar навигация** — превращает манифест в справочник. Но проект — это **путешествие**, а не индекс. Линейность важна: пользователь должен проходить через тезисы последовательно, как через "соматическую ловушку". Sidebar разрушает это.
   317→   317→
   318→   318→**D) Карточная сетка** — полностью ломает линейность. Манифест становится лентой, где можно прыгать между тезисами. Это противоречит концепции "шаг 5, описывающий шаг 1".

   320→   320→## Почему не подходит чистый B
   321→   321→
   322→   322→**Двухколоночный манифест** (заголовок слева, содержание справа) — интересен, но требует осторожности. Если сделать две равные колонки, это создаст визуальный разрыв, который мешает чтению.

   841→   841→

   843→   843→|----------|----------|-------------|
   844→   844→| **Формат** | Интерактивное устройство | Статичный документ с кнопками |
   845→   845→| **Взаимодействие** | Соматический интерфейс (тело) | Глаза + скролл |
   846→   846→| **Адаптивность** | Для разных тел (`prefers-reduced-motion`) | Только для мобильных экранов |

   848→   848→
   849→   849→Это не просто вопрос ширины колонки. Это вопрос:
   850→   850→
   851→   851→> **«Какой опыт мы создаём для пользователя на разных устройствах?»**
   852→   852→
   853→   853→На десктопе человек сидит в кресле. На мобильном — держит устройство в руках. **Это разные соматические контексты.** Один и тот же интерфейс должен вести себя по-разному в этих контекстах.

   857→   857→## ЧТО НУЖНО СДЕЛАТЬ НА САМОМ ДЕЛЕ
   858→   858→
   859→   859→### Принцип: **Не адаптация контента — адаптация опыта.**
   860→   860→
   861→   861→Не просто «сделать больше шрифт», а пересобрать интерфейс так, чтобы он соответствовал положению тела пользователя.
   862→   862→
   863→   863→---
   864→   864→
   865→   865→### 1. Контрольные точки (не просто брейкпоинты)
   866→   866→
   867→   867→```css
   868→   868→/* Мобильный (рука держит телефон) — текущий дизайн */
   869→   869→/* Планшет (рука держит планшет) — шире, но вертикально */
   870→   870→/* Десктоп (рука на столе / клавиатуре) — горизонтальное чтение */
   871→   871→/* Большой экран (рука на столе, откинувшись) — комфортное чтение */
   872→   872→```
   873→   873→
   874→   874→### 2. Что менять на десктопе
   875→   875→
   876→   876→**A) Ширина контента** — 520px это действительно слишком узко для 1920px. Нужно расширять до комфортного чтения.
   877→   877→
   878→   878→**B) Типографика** — 16px на 27" мониторе это 8-10 слов на строку, а должно быть 12-15 слов.
   879→   879→
   880→   880→**C) Адаптивный `em` / `rem`** — шрифты должны масштабироваться пропорционально.
   881→   881→
   882→   882→**D) Использование пространства** — на десктопе можно показать больше контента без скролла.
   883→   883→
   884→   884→---
   885→   885→
   886→   886→## МОЙ ВЕРДИКТ ПО ВАРИАНТАМ
   887→   887→
   888→   888→| Вариант | Что это | Оценка |
   889→   889→|---------|---------|--------|
   890→   890→| **A) Простая адаптация** | Увеличить ширину и шрифты | ❌ **Слабо.** Это техническое решение, а не дизайнерское. Не использует потенциал десктопа. |
   891→   891→| **B) Двухколоночный манифест** | Заголовок слева, содержание справа | ✅ **Хорошо.** Подходит для чтения на десктопе. Но ломает «зеркальность» — становится похоже на газету. |
   892→   892→| **C) Sidebar навигация** | Фиксированная панель со списком тезисов | ⚠️ **Интересно.** Но 33 тезиса в сайдбаре — это перегрузка. Пользователь будет скроллить сайдбар, а не читать. |
   893→   893→| **D) Карточная сетка** | 2-3 тезиса в ряд | ⚠️ **Рискованно.** Карточки ассоциируются с соцсетями, а не с эпистемическим исследованием. Может быть дешёво. |

   896→   896→
   897→   897→## МОЙ ПРЕДЛОЖЕННЫЙ ВАРИАНТ — **E) ГИБРИДНЫЙ РЕЖИМ**
   898→   898→
   899→   899→Не просто менять ширину — **менять сам формат взаимодействия**.
   900→   900→
   901→   901→### Для мобильных (≤ 768px)
   902→   902→- Остаётся текущий дизайн. Это идеальный режим для «ловушки»: узкий экран, фокус на тексте, никаких отвлечений.
   903→   903→
   904→   904→### Для планшетов (768px – 1024px)
   905→   905→- Увеличить `max-width` до 680px
   906→   906→- Чуть крупнее шрифт (17-18px)
   907→   907→- Более щедрые отступы между карточками
   908→   908→
   909→   909→### Для десктопа (≥ 1024px)
   910→   910→- **Два режима на выбор пользователя:**
   911→   911→  1. **«Режим чтения»** — одна колонка, но широкая (900px), крупный шрифт (18-19px), минимум отвлечений.
   912→   912→  2. **«Режим обзора»** — две колонки с тезисами, где слева номер + заголовок, справа — содержание. Это позволяет бегло сканировать 33 тезиса.
   913→   913→
   914→   914→### Для большого экрана (≥ 1440px)
   915→   915→- **Три колонки** для тезисов (но с возможностью переключиться на одну).
   916→   916→- В «ловушке» (шаги 0-5) — **центрированный контент** с мягким ограничением ширины (макс 800-900px) для комфортного чтения.

  1588→  1588→## Вариант E — «читательская ширина + ловушка остаётся узкой»
  1589→  1589→
  1590→  1590→**Принцип:** экраны 0–5 (соматическая ловушка) остаются узкими; экран 6 (манифест) расширяется до читательской ширины.
  1591→  1591→
  1592→  1592→### 1. Ловушка (экраны 0–5): `max-width: 540px`
  1593→  1593→
  1594→  1594→Узкая колонка для ловушки — **это не баг, а соматический интерфейс**. Когда тело закрывает глаза и указывает рукой, узкая колонка фокусирует внимание. Thesis 31. Если бы ловушка была на весь десктоп, она бы рассеялась.
  1595→  1595→
  1596→  1596→```
  1597→  1597→540px осталось навсегда — для экранов 0-5
  1598→  1598→```
  1599→  1599→
  1600→  1600→### 2. Манифест (экран 6): `max-width: 740px` для body, `840px` для epistemic-gap
  1601→  1601→
  1602→  1602→**740px — не случайное число.** Это ширина, при которой абзац 17-18px шрифта содержит 60-80 символов в строке. Это типографский оптимум, к которому пришли New Yorker, The Atlantic, Medium, Are.na, газета «Коммерсантъ» — все серьёзные лонгриды. Доказано в исследованиях чтения (Dyson & Haselgrove, 2001; Bayard & Tijus, 2013): при 60-80 символах в строке максимизируется понимание и минимизируется усталость глаз.
  1603→  1603→
  1604→  1604→**Почему не 1000px (как ты предложил в варианте A)?** Потому что при 1000px абзац 18px шрифта содержит 110-120 символов в строке — глазу приходится слишком далеко прыгать от конца одной строки к началу следующей. Comprehension падает. Это визуально «богаче», но когнитивно беднее.
  1605→  1605→
  1606→  1606→Epistemic-gap (mono, 10-12px) терпит более широкую строку — поэтому ему можно 820-840px.
  1607→  1607→
  1608→  1608→### 3. Жидкая типографика через `clamp()`
  1609→  1609→
  1610→  1610→Вместо скачков по media queries — плавная интерполяция:
  1611→  1611→
  1612→  1612→```css
  1613→  1613→.accordion-content {
  1614→  1614→  font-size: clamp(16px, 0.4vw + 14.5px, 18px);
  1615→  1615→  line-height: clamp(1.75, 1.78, 1.85);
  1616→  1616→  max-width: 740px;
  1617→  1617→}
  1618→  1618→
  1619→  1619→.epistemic-gap {
  1620→  1620→  font-size: clamp(10.5px, 0.2vw + 10px, 12px);
  1621→  1621→  max-width: 820px;
  1622→  1622→}
  1623→  1623→
  1624→  1624→.screen-manifest .accordion {
  1625→  1625→  max-width: min(840px, calc(100vw - 48px));
  1626→  1626→  margin: 0 auto;
  1627→  1627→}
  1628→  1628→```

  1630→  1630→### 4. Одно необязательное UX-улучшение, не нарушающее тезис 13

  1643→  1643→## Что касается «пустых полей по бокам»
  1644→  1644→
  1645→  1645→Ты говоришь: «огромные пустые поля по бокам = плохо». Это **UX-интуиция**, но не полиматическая.
  1646→  1646→
  1647→  1647→Пустые поля вокруг серьёзного текста — **не отходы, а контемплятивная маргиналия**. Талмуд, средневековые манускрипты, современные фотокниги Steidl — все используют широкие поля как часть значения. Пустота по бокам манифеста LC — это визуальное заявление: «здесь нечего продать, нечего кликнуть, не от чего отвлечься».
